The closure was unnecessary (the block runs immediately in the same iteration), so it was removed. Production itself was verified correct by direct curl throughout: all 11 anonymous gates redirect to /login.   **Root cause recorded (test-order failure, found while building the harness):** `test_admin_account_gets_the_admin_role` passed alone but failed in the full suite. Cause, proven by direct observation: `app.py` wires `database.set_db_path()` and `auth.set_admin_email()` at **import** time (`app.py:160-162`), and Python caches modules — so whichever test file imports `app` first freezes both values for the whole session. `tests/test_apply_flow.py` and `tests/test_notifications.py` both import `app` before the routes fixture set its env, so the fixture's `import app` was a no-op and `auth._admin_email` stayed `''`, making `create_user` assign role `user` to every account. A probe printed `auth._admin_email = ''` both before and after the late import, confirming it. **Ruled out:** `tests/test_google_auth.py`'s `monkeypatch` of `auth._admin_email` — running that module first leaves the suite green, which killed that hypothesis. **Blast radius: tests only** — in production `app.py` is the entry point and imports first, so the real app was never affected; it was silent because nothing previously asserted role assignment through the HTTP layer. **Fix:** the routes fixture now re-wires `set_db_path` / `set_db_getter` / `set_admin_email` explicitly after import instead of relying on import-time env — which also removes the risk of route tests running against the repo's real `jobs.db` under an unlucky import order. Verified order-independent (`test_apply_flow + test_notifications + test_routes` = 44 passed).
